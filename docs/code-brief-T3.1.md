## 2. 수정 지시 — Major 3건 (필수)

### M-1 미확정 금액이 성과로 표시됨 → Output을 "실적 / 예정" 두 층으로
**현상**: `projectOutput()` 이 정산 매출이 없으면 계약금액을 `revenue` 로 쓰고, `teamOutputByMonth()` 가 상태 무관하게 행사 종료월에 합산한다. 결과: 2026-09 Output 1억 6,000만 원(완료 6,800만 + 09-25 진행 건 9,200만), 2027-02 에 견적 2,100만 원, D 표 "공수당 매출 1억 400만 원"(5,200만 ÷ 0.5 M/D).
**수정**:
1. `src/metrics.js` `projectOutput()` — 반환에 추가: `realized`(true = 상태 완료·정산완료 **또는** 정산 탭 매출 입력됨), `contractAmount`(항상). `revenue`·`margin`·`marginRate`·`revenuePerMd`·`marginPerMd` 는 **realized 일 때만** 값, 아니면 `null`. 견적·드롭은 `realized=false` 고정.
2. `src/metrics.js` `teamOutputByMonth()` — 반환 구조를 `{ [월]: { actualRevenue, actualMargin, plannedRevenue } }` 로. `actual*` = realized 프로젝트, `plannedRevenue` = 상태 계약·준비·진행의 계약금액. **견적·드롭 제외**. 귀속 월은 행사 종료월 유지.
3. 화면 D 표 열: `프로젝트 · 상태 · 계약금액 · 정산 매출 · 실마진(직접비 차감) · 실투입 공수 · 공수당 매출 · 쇼업률 · 게런티 달성률` — 정산 매출·실마진·공수당 매출은 realized 만 값, 나머지 "—". 정산 전 행은 보조 텍스트색.
4. 화면 D "팀 월별 투입 대비 성과" — 막대 투입 공수 유지, 선 3개: **실적 매출(실선·잉크)** · **예정 매출(점선·보조색)** · **실마진(실선·액센트)**. 범례에 "예정 = 계약~진행 단계 계약금액" 각주.
5. `docs/DATA-CONTRACT.md` §4.4·§4.5 갱신. `tests/metrics.test.js` 에 케이스 추가: 견적 제외 · 진행 건은 planned 로만 · 완료 건은 actual · 정산 매출 입력된 진행 건은 realized.

### M-2 산점도가 정산 전 프로젝트를 실마진 0원에 찍음
**수정**: 화면 D 산점도는 `realized` 프로젝트만 그린다. 차트 아래 한 줄: "정산 전 프로젝트 N건(이름, …)은 표시하지 않습니다." realized 0건이면 빈 상태 문구 "정산이 끝난 프로젝트가 생기면 여기에 표시됩니다."

### M-3 필터가 가동률·경고·핵심지표까지 바꿈
**현상**: `filteredData()` 가 배정·공수기록까지 걸러낸 뒤 `kpis`·`plannedUtilization`·`warnings` 를 계산. 유형 필터 ① 적용 시 팀원2|2026-11 `110% over` → `0% ok`, E 과부하 0건, "팀 계획 가동률" 33%→23%, 필터 적용 표시 없음.
