# 설계안 초안 — 마일스톤 세부 항목(WBS R&R) · 계획 공수 자동 합산 (5턴 후보)

- 작성: 2026-09-14 · Code 세션(Fable 5.1) · 기획자님 요청 정리
- 상태: **결정 대기** — 아래 §4 세 가지 답을 받으면 착수 지시문(`code-brief-T5.md`)으로 확정
- 요청 원문: "마일스톤에서 세부적인 항목들을 설정하고 거기서 M/M 을 설정해서 전체 공수에 자동 합산 · 마일스톤에서 WBS R&R 세부 내역을 설정하고 각각의 파트에서 선택·추가·수정"
- 추가 요청(같은 날): "업무분장을 할 때 **임팩트와 난이도**도 설정하고, 그것에 따른 **실무자 배정 기준**이 될 수 있게"
- 추가 요청(같은 날): "각각 파트에서 필요한 내용에 **주석**을 달아서 판단할 수 있도록"

## 1. 무엇을 만드나 (한 줄)
마일스톤 아래에 **세부 항목**(해야 할 일 + 맡는 파트 + 담당자 + 계획 공수)을 두고, 그 합계가 프로젝트·파트·담당자별 **계획 공수**로 자동 올라가게 한다. 각 파트는 대시보드에서 자기 항목을 골라 넣고 고친다.

## 2. 데이터 모델 제안
### 2.1 새 탭 `마일스톤 세부` (A:K)
| 열 | 형식 | 설명 |
|---|---|---|
| 프로젝트ID* | 목록 | |
| 마일스톤* | 텍스트 | 같은 프로젝트의 `마일스톤` 탭 항목 이름 |
| 세부 항목* | 텍스트 | 예: "발주처 참가자 명단 수령", "무대 도면 확정" |
| 파트* | 목록 | 설정 탭 역할 6종(영업·모객·운영 PM·현장 운영·디자인·제작·정산·리포트) — §4-③ |
| 담당 | 목록 팀원 | 비우면 파트만 정한 상태 |
| 임팩트* | 목록 | **상 / 중 / 하** — 행사 성과·고객 관계·매출에 미치는 영향 |
| 난이도* | 목록 | **상 / 중 / 하** — 전문성·조율 범위·실수 시 복구 비용 |
| 요구 등급 `[자동]` | 산식 | 임팩트 × 난이도 → **리드 / 담당 / 보조 가능** (§3.5 표). 담당자 추천·경고의 기준 |
| 계획 M/D* | 숫자(0.5 단위) | 저장 단위는 M/D(결정 D3 · 설정 "월 가용 M/D" 20 = 1 M/M) — §4-① |
| 예정일 | 날짜 | 비우면 마일스톤 예정일 |
| 상태 | 목록 | 예정 / 진행 / 완료 |
| 비고 | 텍스트 | |
| (자동) 행사명 | 수식 | 마일스톤 탭 G열과 같은 방식 |

유일키 = 프로젝트ID + 마일스톤 + 세부 항목. 마일스톤 이름이 바뀌면 세부 항목도 따라가야 하므로 마일스톤 수정 시 연쇄 갱신(서버).

### 2.2 설정 탭 `표준 세부 항목` (템플릿)
`마일스톤 | 세부 항목 | 파트 | 기본 M/D | 주최형 제외` — 표준 마일스톤 9종마다 기본 항목 몇 개. "표준 마일스톤 생성" 때 함께 생성(옵션). 초안은 플레이북 08 역할 기준으로 Code 가 만들고 기획자님이 시트에서 다듬는다.

### 2.3 팀원 등급 — "맡을 수 있는 범위" (§4-④)
실무자 배정 기준이 되려면 사람 쪽에도 기준값이 필요하다. 평가 점수가 아니라 **맡을 수 있는 범위**를 뜻하는 라벨 3단계로 둔다: **보조 · 담당 · 리드**.
| 안 | 저장 위치 | 내용 |
|---|---|---|
| 1차(권장 시작) | `팀원` 탭 F열 `숙련도` | 주역할 기준 등급 1개. 비우면 `담당` |
| 2차(선택) | 새 탭 `팀원 역량` (이름 · 파트 · 등급) | 파트마다 다른 등급(예: 운영 리드 · 디자인 보조). 비어 있으면 1차 값 |

> 민감 정보 주의: 이 값은 시트 편집자 전원에게 보인다. 급여·단가·평가 점수는 두지 않고(결정 D3), 라벨도 "보조/담당/리드"처럼 **역할 범위**로만 쓴다. 상태 `지원`(타 팀 인력)은 기본 `보조`.

### 2.4 새 탭 `주석` — 파트별 판단 근거·요청·질문 (§4-⑥)
세부 항목 하나에 여러 파트가 의견을 남겨야 하므로 `비고` 한 칸으로는 부족하다. 항목마다 **주석 스레드**를 둔다.
| 열 | 형식 | 설명 |
|---|---|---|
| 주석ID `[자동]` | 텍스트 | `N-000001` |
| 프로젝트ID* | 목록 | |
| 마일스톤* | 텍스트 | |
| 세부 항목 | 텍스트 | 비우면 마일스톤 전체에 대한 주석 |
| 파트* | 목록 | 어느 파트의 의견인지(역할 6종) |
| 작성자 `[자동]` | 텍스트 | 대시보드 접속 계정 이메일(변경이력과 같은 방식) + 팀원 이름(선택 — 이메일↔이름 대응표가 없으므로 폼에서 고름) |
| 일시 `[자동]` | 일시 | |
| 유형* | 목록 | **판단 근거 · 요청 · 질문 · 결정** — "판단할 수 있도록"의 재료를 구분 |
| 내용* | 텍스트 | 줄바꿈 허용 |
| 해결 | 체크(예/빈칸) | 질문·요청이 처리되면 체크. 미해결 건수가 항목 옆에 표시 |

- 규칙: 주석은 **추가·수정(작성자 본인)·해결 표시**만. 삭제는 시트에서(변경이력 백업 규칙 동일).
- 화면: 세부 항목 행을 펼치면 임팩트·난이도·요구 등급·담당 추천 **바로 아래에 주석 스레드**가 붙는다(파트 칩 색으로 구분, 최신이 아래). 항목 목록에는 "주석 3 · 미해결 1" 배지.
- 파트 관점: A 상세 패널 위 **파트 필터**를 고르면 그 파트의 항목과 그 파트에 온 질문·요청(미해결)이 먼저 보인다. E 화면 "이번 주"에 **"내 파트에 온 미해결 질문·요청"** 목록 추가.
- 표준 세부 항목 템플릿에 **"판단에 필요한 내용"** 열을 두어(예: 답사 → "동선·전기 용량·반입 시간 확인"), 항목을 만들 때 첫 주석(유형 요청)으로 자동 생성할지는 §4-⑥.

## 3. 합산(롤업) 규칙 — 배정과의 관계가 핵심 (§4-②)
| 안 | 규칙 | 장점 | 단점 |
|---|---|---|---|
| **A (추천)** | 세부 항목의 (담당, 파트) 별 계획 M/D 합 → **`배정` 행을 자동 생성·갱신**(기간 = 그 담당의 세부 항목 예정일 최소~최대, 없으면 착수일~행사 종료일). 담당이 빈 항목은 파트 합계로만 표시 | 가동률·히트맵·소진율·과부하 경고 등 **기존 산식 전부 그대로** 동작. 배정 편집기도 계속 쓸 수 있음 | 배정 행을 손으로 고친 값과 자동값이 충돌 — "자동" 표시 열 또는 비고 규칙 필요 |
| B | 세부 항목이 배정을 **대체**. 계획 공수 = Σ 세부 항목 | 저장소가 하나 | SPEC §4 산식·계약 §4.2~4.3·테스트·화면 B 전면 개정. 2턴 분량 |
| C | 세부 항목은 **참고 층**. 프로젝트 상세에 "세부 항목 합계 vs 배정 합계"만 나란히 표시 | 가장 작음 | "자동 합산" 요구를 절반만 충족 |

A 안일 때 자동 갱신 조건: 배정 행 비고가 `자동(세부 항목)` 인 행만 덮어쓴다. 손으로 만든 배정 행은 건드리지 않고 합계 비교만 보여 준다.

### 3.5 실무자 배정 기준 — 임팩트 × 난이도 → 요구 등급 → 추천·경고
**요구 등급 표(기본값, 설정 탭에서 바꿀 수 있게)**
| 난이도 ＼ 임팩트 | 하 | 중 | 상 |
|---|---|---|---|
| **하** | 보조 가능 | 보조 가능 | 담당 |
| **중** | 담당 | 담당 | 리드 |
| **상** | 리드 | 리드 | 리드 |

**담당자 추천 순서**(세부 항목 폼에서 담당을 고를 때 목록 정렬)
1. 파트가 맞는 팀원(주역할 또는 `팀원 역량` 등급이 있는 사람)
2. 등급이 요구 등급 이상인 사람을 위로
3. 같은 프로젝트에 이미 배정된 사람 우선(맥락 유지)
4. 이번 달 계획 가동률이 낮은 순 — 이름 옆에 "가동률 62%" 표시

**경고(막지 않고 표시만 — §4-⑤)**
- 등급 미달: "요구 등급 리드, 담당자 보조" 배지
- 편중: 한 사람이 프로젝트의 리드 항목 60% 이상을 맡으면 프로젝트 상세에 "리드 항목 편중" 표시
- 과부하: 추천 목록에서 가동률 100% 초과인 사람은 회색 처리
- 미배정 리드 항목: 임팩트·난이도가 상인데 담당이 비어 있으면 E 화면 "이번 주" 경고 목록에 추가

이 규칙은 전부 순수 함수(`src/metrics.js`)로 두어 테스트로 검산한다. 임팩트·난이도는 계획 M/D 를 바꾸지 않는다(공수는 입력값 그대로). 표준 세부 항목 템플릿에는 기본 임팩트·난이도를 함께 둔다.

## 4. 기획자님이 정해 주실 것 6가지
1. **단위 표기** — 요청은 "M/M". 보드는 M/D 로 기록·계산합니다(결정 D3, 주간 공수도 M/D). 제안: **저장·산식은 M/D 유지, 입력 폼과 합계에 M/M 환산(÷20)을 나란히 표시**. 아니면 M/M 을 정식 단위로 바꾸는 개정(모든 화면·문서)이 필요합니다.
2. **배정과의 관계** — §3 의 A / B / C 중 선택. 추천은 A.
3. **"파트"의 정의** — 설정 탭 역할 6종을 그대로 파트로 쓸지, 별도 파트 목록(예: 기획·운영·디자인·영업·모객·정산)을 둘지. 그리고 표준 세부 항목 초안을 Code 가 먼저 만들어도 되는지.
4. **팀원 등급 저장 방식** — §2.3 의 1차(팀원 탭 `숙련도` 1열, 주역할 기준)로 시작할지, 처음부터 2차(파트별 `팀원 역량` 매트릭스)로 갈지. 추천은 1차로 시작하고 필요해지면 2차 추가.
5. **등급 미달 배정** — 경고만 표시(추천)할지, 저장을 막을지. 임팩트·난이도 3단계(상/중/하)와 요구 등급 표(§3.5)의 기본값도 확인.
6. **주석** — 유형 4종(판단 근거·요청·질문·결정)으로 갈지 자유 텍스트만 둘지 · 작성자를 이메일만 남길지 팀원 이름도 고르게 할지 · 표준 세부 항목의 "판단에 필요한 내용"을 첫 주석으로 자동 생성할지.

## 5. 경계 확인
`docs/SPEC-v1.md` §2 와 `CLAUDE.md` §1 은 "태스크 단위 관리(WBS)는 커뮤니케이터 영역"으로 선을 그어 두었습니다. 이 기능은 **마일스톤 단위 R&R 체크리스트 + 계획 공수**로 한정하면 보드의 목적("누가 어디에 얼마나 들어가는가")과 맞습니다. 착수 시 결정 D11 로 "마일스톤 세부 항목까지 보드 범위, 일정·의존관계·산출물 관리는 여전히 커뮤니케이터" 라고 경계를 다시 적습니다.

## 6. 화면 배치(초안)
- **A 상세 패널**: 마일스톤 행 펼침 → 세부 항목 표(파트 필터 칩 · 담당 · 계획 M/D · 상태 체크) · [항목 추가] · 행별 수정/삭제 · 마일스톤별 소계 · 프로젝트 합계(M/D · M/M 환산)
- **B 배정 보드**: A 안이면 "세부 항목 합계로 배정 채우기" 버튼 + 자동 행 표시. 히트맵은 그대로
- **C 공수 관리**: 프로젝트별 계획(세부 합계) vs 실투입 막대에 파트별 분해(선택)
- 쓰기는 4턴에 만든 공통 편집 경로(`saveRow`/`deleteRow`)에 표 하나를 더하는 방식 — 서버·검증·이력은 재사용
- **임팩트·난이도**: 세부 항목 표에 칩(상/중/하 색 3단), 요구 등급 자동 표시. 담당 select 는 §3.5 순서로 정렬 + 가동률 표시 + 등급 미달 배지
- **B 팀원 관리**에 `숙련도` 열 추가(4턴 폼이 자동 생성). 프로젝트 상세 요약에 "리드 항목 n · 담당 편중 여부"
- **주석**: 세부 항목 펼침 아래 스레드(파트 칩·유형·작성자·일시·해결 체크) + 한 줄 입력칸 · 항목 배지 "주석 n · 미해결 n" · A 파트 필터 · E "내 파트에 온 미해결 질문·요청"

## 7. 규모 가늠
계약·Schema 표 2개(세부 항목 · 주석, + 팀원 탭 열 1개) + 설정 템플릿·요구 등급 표 + 서버 롤업(A 안) + 추천·경고 산식 + 화면 3곳 + 테스트·게이트 = 4턴과 비슷한 분량. 결정이 오면 세션 1~2회.
