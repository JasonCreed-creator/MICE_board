## 0. 한 줄 목표
마일스톤 아래에 **파트별 업무 블럭**(해야 할 일 + 담당 + 임팩트·난이도 + 계획 M/D)을 카탈로그에서 골라 넣고, 그 합계가 **배정 행으로 자동 반영**되어 가동률·소진율에 그대로 잡히게 한다. 블럭마다 파트별 **주석**(판단 근거·요청·질문·결정)을 달아 판단 근거를 남긴다.

## 2. 데이터 (계약 §3.10~3.12 · `src/schema.js` 에 정의됨)
### 2.1 `세부항목` (A:M) — `Schema.TABLES.items`
`세부ID | 프로젝트ID | 마일스톤 | 파트 | 블럭 | 담당 | 임팩트 | 난이도 | 계획 M/D | 예정일 | 상태 | 비고 | 행사명(자동)`
- 세부ID `[자동]` `W-000001`(탭 전체 최대+1, 6자리). 키 = 세부ID. 같은 (프로젝트ID·마일스톤·블럭) 중복 금지(검증)
- 파트 = 역할 6종 · 임팩트·난이도 = 상/중/하(빈 값 → 중) · 계획 M/D 0.5 단위 · 상태 예정/진행/완료(빈 값 → 예정) · 예정일 비우면 마일스톤 예정일
- M열 행사명은 마일스톤 G열과 같은 1행 배열 수식(`ensure…` 헬퍼로 생성, 읽지 않음)
### 2.2 `주석` (A:K) — `Schema.TABLES.notes`
`주석ID | 프로젝트ID | 마일스톤 | 세부ID | 파트 | 작성자 | 작성자 이름 | 일시 | 유형 | 내용 | 해결`
- 주석ID `[자동]` `N-000001`. 세부ID 비우면 마일스톤 전체 주석. 작성자·일시는 서버가 채움(`userEmail_`·`nowStrApi_(true)`). 해결 = `예` 또는 빈 값
- 수정은 **작성자 본인만**(서버: 현재 이메일 ≠ 작성자면 거부, 단 `해결` 만 바꾸는 요청은 누구나). 삭제는 시트에서만(대시보드 `deleteRow('notes')` 거부)
### 2.3 `업무블럭` (A:H) — `Schema.TABLES.blocks` (카탈로그 · 시트에서만 편집)
`파트 | 블럭 | 기본 마일스톤 | 기본 M/D | 기본 임팩트 | 기본 난이도 | 판단에 필요한 내용 | 주최형 제외`
- 탭이 없으면 `getBootstrap` 이 코드의 기본 카탈로그(`DEFAULT_BLOCKS`, 아래 §2.4)를 그대로 돌려준다(`meta.blocksSource: 'default'|'sheet'`). `setupSheets` 와 메뉴 [팀 보드 → 드롭다운 목록 새로고침] 이 탭을 만들고 기본값을 채운다(이미 있으면 건드리지 않음)

## 3. 서버 API (계약 §5 확장 · `Code.gs`)
| 함수 | 인자 | 반환 | 규칙 |
|---|---|---|---|
| `getBootstrap()` | — | 기존 + `items[]` · `notes[]` · `blocks[]` · `meta.blocksSource` | 탭 없으면 `items`·`notes` 는 `[]`, `blocks` 는 기본 카탈로그 |
| `saveRow('items', row, expected, options)` | 4턴과 동일 | `{ ok, created, row, assignments:[그 프로젝트의 배정 행 전체], firstNote? }` | 저장 후 **`syncAssignmentsFromItemsApi_(projectId)`** 실행 → 응답에 그 프로젝트 배정 행 전체. 신규이고 `options.firstNote`(문자열)가 있으면 주석(유형 요청·파트 = 블럭 파트)을 함께 생성 |
| `addItems(projectId, milestone, part, blockNames[])` | 카탈로그 블럭 여러 개를 한 번에 | `{ ok, items:[생성 행], notes:[첫 주석들], skipped:[이미 있는 블럭], assignments:[...] }` | 기본 M/D·임팩트·난이도·"판단에 필요한 내용"(→ 첫 주석) 을 카탈로그에서 채움. 예정일은 비움(마일스톤 예정일 따름). 잠금 1회 안에서 처리 |
| `deleteRow('items', key)` | `{ id }` | `{ ok, removed:{ notes:n }, assignments:[...] }` | 그 세부ID 의 주석 연쇄 삭제(백업) → 배정 동기화 |
| `saveRow('notes', row, expected)` | 신규: 작성자·일시 서버 채움 / 수정: 본인만, `해결` 토글은 누구나 | `{ ok, created, row }` | `deleteRow('notes')` 는 거부("주석은 시트에서만 지웁니다") |
| 마일스톤 수정(`saveRow('milestones')`) | 이름이 바뀌면 | 응답에 `renamed:{ items:n, notes:n }` | 세부항목·주석의 마일스톤 열 연쇄 갱신 |
| 마일스톤 삭제 | 세부항목이 있으면 | Error("세부 항목 n건이 있어 삭제할 수 없습니다. 항목을 먼저 지우세요.") | `Schema.deleteCheck('milestones')` 가 판정 |
| 프로젝트 삭제 | 연쇄에 세부항목·주석 추가 | `removed.items`·`removed.notes` | 백업 JSON 에 포함 |

**배정 동기화 `syncAssignmentsFromItemsApi_(projectId)`** (D13 · `Schema.assignmentsFromItems` 사용 — mock 과 같은 결과여야 함)
1. 그 프로젝트의 세부항목 중 담당이 있는 것을 (담당, 파트) 로 묶어 계획 M/D 합산
2. 기간: 항목 날짜 = 예정일 || 마일스톤 예정일. start = min(날짜) − 14일, end = max(날짜). 프로젝트 착수일(유효값)~정산 예정일(유효값) 안으로 자른다. 날짜가 하나도 없으면 착수일~행사 종료일
3. 기존 배정 행 중 비고가 `자동(세부항목)` 인 행 = 자동 행. 자동 행은 **전부 지우고 다시 만든다**(ID 는 같은 (담당, 파트) 가 있으면 유지). 수동 행(비고가 다른 행)은 그대로 둔다. **같은 (담당, 파트)에 수동 행이 있으면 자동 행을 만들지 않고 `overlaps`(세부 합계 vs 수동 M/D)로만 알린다** — 이중 집계 방지. 수동 행을 지우면 다음 동기화 때 자동 행이 생긴다(`Schema.assignmentsFromItems` 가 이 규칙을 구현)
4. `saveAssignments` 와 같은 쓰기 방식(프로젝트 행 교체 · 원시값 보존) · 이력 1줄 `배정 / 저장 / "세부항목 동기화: n행"`(변경이 없으면 기록하지 않음)
5. 반환: 그 프로젝트 배정 행 전체(자동+수동)

## 4. 화면 (`src/app.js` · `src/styles.css`)
- **A 상세 패널 — 마일스톤 표 각 행 펼침**(`data-action="toggle-items"`): 그 마일스톤의 세부 항목 표. 열: 파트 칩 · 블럭 · 담당(select) · 임팩트 칩 · 난이도 칩 · 계획 M/D · 예정일 · 상태 · 주석 배지("주석 n · 미해결 n") · [수정] [삭제]. 표 아래 **[블럭 추가]** → 파트 select → 그 파트의 카탈로그 블럭을 **체크 칩**으로(이미 있는 블럭은 ✓·비활성, 기본 M/D 표시) → [추가](`addItems`). 마일스톤 소계 · 프로젝트 합계는 상세 패널 위쪽에 "계획 공수 합계 12.5 M/D (0.6 M/M) · 파트별 · 담당별" 카드
- **세부 항목 수정 폼**(4턴 공통 폼 재사용): 담당 select 는 정렬 = 파트가 주역할인 팀원 → 같은 프로젝트 기배정자 → 이번 달 계획 가동률 낮은 순, 이름 옆 "가동률 62%"·100% 초과는 회색 표기(`app.js` `memberPickList()`). 등급·경고 없음(D15)
- **주석 스레드**: 세부 항목 행 [주석 n] 클릭 → 그 행 아래 스레드(파트 칩 · 유형 · 작성자 이름 또는 이메일 앞부분 · 일시 · 내용 · [해결] 체크). 입력 줄: 유형 select(기본 요청) · 작성자 이름 select(팀원, 선택) · 내용 · [남기기]. 본인 주석만 [수정]
- **A 파트 필터 칩**(상세 패널 위): 고르면 세부 항목 표가 그 파트만 · 그 파트에 온 미해결 질문·요청이 위로. 선택은 `localStorage`(`tb.part`)에 기억(사람마다 자기 파트)
- **B 배정 보드**: 자동 행은 편집 표에서 회색 배경 + "자동" 배지 + 입력 잠금(수정하려면 세부 항목에서). 세부 항목 합계가 있는데 같은 (담당, 파트)의 수동 행이 있어 자동 행이 생기지 않은 경우(`overlaps`) 그 수동 행 옆에 "세부 합계 4 M/D · 수동 5 M/D — 수동 행을 지우면 자동으로 바뀜" 배지
- **E 이번 주**: 카드 2개 추가 — "핵심 항목 미배정"(임팩트 상 또는 난이도 상인데 담당이 빈 항목, 프로젝트·마일스톤·블럭·파트) · "미해결 질문·요청"(파트 필터 적용, 최신 순 20건)
- **핵심 지표**: 변경 없음. **D 화면**: 변경 없음
- 응답 반영: `items`/`notes` push·교체·삭제, `assignments` 는 응답의 프로젝트 행 전체로 교체(다른 프로젝트 행 보존) → `render()`. mock 어댑터는 `Schema.assignmentsFromItems` 로 같은 동기화 + `[mock write]` 로그 + 이력
