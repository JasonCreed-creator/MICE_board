## 0. 한 줄 정의

구글 스프레드시트에 **프로젝트·배정·주간 공수·마일스톤·정산**을 기록하고, Apps Script 웹앱 대시보드 한 판에서 **담당자 배정 → M/D 가동률 → Input(M/D) vs Output(매출·마진·행사 성과)** 를 관리한다. v1.3 부터 마일스톤 아래 **파트별 업무 블럭 · 계획 공수 · 주석**을 두고, 그 합계가 배정으로 자동 반영된다(D11~D16).

### 1.1 D6~D10 · D6a·D6b (2026-09-13 · v1.2 · 기획자님 확인 대기 — 기본값으로 착수)

**Output 실적/예정 2층 규칙 (v1.1 신설)** — 미확정 금액을 성과로 읽지 않기 위해, 프로젝트 단위 성과는 "정산 확정" 판정을 먼저 통과해야 값이 생긴다.
- **정산 확정(realized)** = 프로젝트 상태가 `완료`·`정산완료` 이거나, `정산` 탭의 매출이 입력되어 있으면 참. 상태 `견적`·`드롭` 은 **항상 거짓**.
- 정산 확정이 아니면 정산 매출 · 실마진(직접비 차감) · 실마진율 · M/D당 매출 · M/D당 실마진은 **값 없음**(화면 "—"). 계약금액만 표시한다.
- 월 귀속 기준은 **행사 종료월**(실적·예정 공통). `견적`·`드롭` 은 실적·예정 두 층 모두에서 제외한다.
- 산식 상세는 `docs/DATA-CONTRACT.md` §4.4(`projectOutput`)·§4.5(`teamOutputByMonth`).

**핵심 지표(상단 KPI 스트립)**
- "이달 행사" = 행사 기간이 이번 달과 겹치는 프로젝트 수 — **`견적`·`드롭` 제외**.
- "팀 계획 가동률" = 당월 계획 M/D 합 ÷ 팀 가용 M/D 합(위 계획 가동률의 대상 배정 규칙을 그대로 따른다).

배정 월 배분 규칙: 배정 시작~종료 구간의 **달력일 수 비례** 균등 배분(영업일 계산은 2차). 1개월 이내 배정은 전량 해당 월.

**배정 자동 반영 규칙 (v1.3 · D13 · A안)** — 세부 항목이 배정의 원천이 된다. 판정은 `src/schema.js` `assignmentsFromItems`(계약 §9.12), 쓰기는 계약 §5 "배정 동기화 규칙". 서버와 mock 이 같은 결과를 낸다.
- 세부 항목 중 **담당이 있는** 것을 (담당·파트)로 묶어 계획 M/D 를 합산 → `배정` 탭에 **자동 행**(비고 `자동(세부항목)`, 상태 예정)으로 쓴다. 기간 = 항목 날짜(예정일 또는 마일스톤 예정일)의 최소 −14일 ~ 최대, 착수일~정산 예정일 안으로 자름. 날짜가 없으면 착수일~행사 종료일
- 자동 행은 세부 항목을 저장·추가·삭제할 때마다 전부 다시 계산한다(같은 (담당·파트)의 배정ID 는 유지). **수동 행**(비고가 다른 행)은 건드리지 않는다. 결과가 같으면 시트도 이력도 건드리지 않는다
- **겹침 생략**: 같은 (담당·파트)에 수동 행이 있으면 자동 행을 만들지 않고 B 화면 그 수동 행 옆에 "세부 합계 n M/D · 수동 m M/D — 수동 행을 지우면 자동으로 바뀜" 배지만 띄운다(이중 집계 방지). 수동 행을 지우면 다음 동기화 때 자동 행이 생긴다
- 자동 행은 위 계획 가동률·팀 계획 가동률·소진율·과부하 경고에 **보통 배정 행과 똑같이** 들어간다(산식 변경 없음). 담당이 빈 항목은 배정에 들어가지 않고 파트 합계로만 보인다

경고 판정(설정 탭 임계치):
- 과부하: 계획 가동률 > 100% (적) · 주의: 85~100% (황)
- 미배정: 상태가 계약 이상인데 `배정` 행이 PM 1명뿐이거나 0건
- 지연: 마일스톤 상태=지연
- 미기록: 지난주 주차에 공수기록 0행인 재직 팀원
  - *(3턴: 팀 최신 주차 기준 대안은 불승인, 원문 유지)* — 기준 주차 R 은 **오늘이 속한 주의 월요일 − 7일**로 고정한다. 팀 전체 최신 기록 주차와 max 를 취하는 2턴 구현안은 채택하지 않는다(전원이 밀리면 경고가 사라지기 때문). 상세는 계약 §4.7.
- 소진 초과: 소진율 > 100% (행사 전이면 적, 행사 후면 회색)

화면 명칭(v1.1 · 승인 이탈 ④): 탭 라벨은 약어를 피해 **C 공수 관리 · D 투입 대비 성과** 로 쓴다. 지표 라벨(쇼업률·게런티 달성률·M/D)은 SPEC 용어를 유지하고 용어 설명을 가이드 §9.3 에 둔다.

### 5.1 필터 적용 범위 (v1.1 신설)

원칙: **사람 단위 지표는 전체 데이터, 프로젝트 단위 지표는 필터 적용.** 유형·PM·상태·기간 필터가 가동률·경고까지 바꾸면 "이 사람이 실제로 얼마나 차 있는가"를 오독하게 되므로 분리한다.

| 전체 데이터 고정 | 필터 적용 |
|---|---|
| 핵심지표 "팀 계획 가동률" · B 히트맵 · E 과부하·미기록 경고 · C "팀원별 이달 투입 구성" · C "주간 기록 현황" | A 카드·타임라인 · 핵심지표 "진행 중 프로젝트"·"이달 행사"·"지연 마일스톤" · B 배정 편집 대상 목록 · C 프로젝트별 소진율 · D 전부 · E 2주 내·지연·미배정·계획 공수 초과 |

- 필터가 하나라도 걸리면 필터 행 오른쪽에 배지 **"필터 적용 중 · 프로젝트 N / M"** 을 띄운다.
- B 히트맵 카드 설명문에 "가동률은 필터와 무관하게 전체 프로젝트 기준입니다." 를 명시한다.
- 히트맵 셀 클릭·배정 편집은 전체 데이터 기준으로 동작한다.

**편집 원칙**
- 시트가 유일한 저장소(SoT). 대시보드는 시트를 직접 읽고 쓴다. 별도 동기화·캐시 없음. 화면은 응답을 로컬 상태에 반영해 재렌더한다(전체 재로드 없음).
- **행 단위 부분 쓰기**: 수정은 바뀐 필드만 셀에 쓴다. 신규는 마지막 행 다음에 한 줄. 삭제는 그 행만(연쇄는 대상 행들만).
- **수식 열 보존**: 마일스톤 F · 정산 D·E·H·I 는 대시보드가 쓰지 않는다. 신규 행에는 서버가 `setupSheets` 와 같은 수식을 채운다.
- 자동 필드(프로젝트ID · 등록일 · 기록일시 · 배정ID)는 서버가 채운다. 폼에서는 읽기 전용.
- 설정 탭은 시트 전용(D6). 배정 탭은 경로 1(기존 편집기)과 **v1.3 자동 행 동기화**(경로 4·5·8 의 부수 쓰기 — 자동 행만 교체, 이력 1줄 `배정 / 저장 / 세부항목 동기화: n행`)만. `업무블럭` 탭은 시트 전용(D14 — 대시보드 쓰기 경로 없음).
- **(v1.3)** 세부 항목·주석 탭이 없는 기존 시트도 재설정 없이 대응 — 첫 쓰기 때 서버가 탭을 만든다(`변경이력` 과 같은 방식). `업무블럭` 탭은 만들지 않고 기본 카탈로그를 쓴다(§3.12).
- 검증은 `src/schema.js` 한 벌을 프런트(저장 전 선검증) · 서버(최종 검증) · 테스트가 공유한다(계약 §9). 필수·형식·열거·참조(팀원·프로젝트)·날짜 순서·0.5 단위·유일키.

**삭제 규칙 (D8)**

| 대상 | 규칙 |
|---|---|
| 프로젝트 | 공수기록이 1건이라도 있거나 정산 매출이 입력돼 있으면 **삭제 불가** → 상태를 `드롭` 으로 안내. 가능하면 배정·마일스톤·정산 행을 **함께 삭제**(연쇄, 확인 문구에 건수 표시). 지운 행은 변경이력 백업 열에 남는다 |
| 팀원 | 담당PM · 배정 · 공수기록 · 마일스톤 담당으로 참조되면 **삭제 불가**(건수 표시) → 상태를 `퇴사` 로 안내 |
| 마일스톤 | **v1.3**: 세부 항목이 1건이라도 있으면 **삭제 불가**("세부 항목 n건이 있어 삭제할 수 없습니다. 항목을 먼저 지우세요."). 없으면 자유(마일스톤 전체 주석은 백업 후 함께 삭제) |
| 세부 항목 (v1.3) | 자유 — 그 항목의 주석을 **함께 삭제**(건수 표시, 백업)하고 배정 자동 행을 다시 계산 |
| 주석 (v1.3) | 대시보드 삭제 없음 — 해결 체크로 닫거나 시트 `주석` 탭에서 삭제(D16) |
| 업무 블럭 (v1.3) | 대시보드 편집 없음 — 시트 `업무블럭` 탭에서만(D14) |
| 배정 · 공수기록 | 편집기에서 행 제거 후 저장(행 단위 삭제 버튼 없음). **v1.3** 자동 행은 편집기에서 잠김 — 세부 항목을 고쳐서 바꾼다 |
| 정산 | 행 삭제 없음 — 값을 비워 저장 |

**동시 편집 (D9)** — 서버 잠금(`withLock_`) + 편집 시작 시점 스냅샷(`expected`) 대조. 시트 값이 그 사이 바뀌었으면 저장을 거부하고 "다른 사용자가 먼저 수정했습니다. 화면을 새로고침한 뒤 다시 시도하세요." 를 보여준다(시트는 바뀌지 않음). 복합키 표(공수기록·마일스톤)는 `expected` 의 키로 행을 찾아 이름·주차를 바꾸는 수정도 허용한다.

**이력 (D7)** — 경로 1~6 전부가 `변경이력` 탭(§3.8)에 한 행씩 남는다. E 화면 "최근 변경" 에 30건.

**이름 변경 불가 (D10)** — 팀원 이름은 5탭이 키로 참조하므로 대시보드 폼에서 잠긴다. 시트 `팀원` 탭에서 바꾸고 찾기·바꾸기로 일괄 수정(가이드 §6.8).

**설정 탭** — 시트 전용. 목록·기준값·마일스톤 템플릿은 대시보드에서 고칠 수 없다.

**2단계 확인 (D6a)** — 삭제 · 연쇄 삭제 · 완료 처리 · 표준 마일스톤 생성 · **v1.3** 세부 항목 삭제(주석 연쇄 건수 포함)는 버튼 자리의 인라인 확인("정말 처리할까요? [확인] [취소]", 연쇄는 건수 문구 포함). 블럭 추가·주석 남기기·해결 체크는 확인 없음(되돌리기 쉬움). 브라우저 대화상자(alert·confirm·prompt) 금지.

**권한 (D6b)** — 배포 설정 그대로(도메인 사용자 + 시트 편집자 = 전원 편집 가능). 사용자 이메일은 이력의 "사용자" 열과 머리말 표시에만 쓰고 권한 판단에 쓰지 않는다. **v1.3 예외 하나**: 주석은 작성자 본인(같은 이메일)만 수정할 수 있다(해결 체크는 누구나, D16) — 유일한 사용자 단위 규칙이며 서버가 판정한다.

**3턴 검수 지적(Major 3건) 반영**
- **Output 2층화**: 프로젝트 성과는 "정산 확정(realized)" 판정을 통과해야 값이 생기고, 팀 월별 Output 은 **실적 매출 · 실적 실마진 / 예정 매출**로 분리한다. `견적`·`드롭` 은 두 층 모두 제외 (§4, 계약 §4.4·§4.5)
- **필터 적용 범위 표 신설**: 사람 단위 지표(가동률·경고)는 전체 데이터 고정, 프로젝트 단위 지표는 필터 적용. 필터 시 "필터 적용 중 · 프로젝트 N / M" 배지 (§5.1)
- **산점도**는 정산이 끝난 프로젝트만 표시, 제외 건수 안내 (§5 D 행)

**그 밖의 표기·동작 규칙**
- 실마진 라벨을 문서·화면 전부 **"실마진(직접비 차감)"** 으로 통일(가정 A 유지 명시) (§3.6)
- 핵심 지표 "이달 행사"에서 `견적`·`드롭` 제외 (§4·§5)
- 완료 처리·표준 마일스톤 생성은 **2단계 인라인 확인**, 브라우저 대화상자 금지 (§5 E 행)
